# CLAUDE.md — Personal Fitness Tracker AI Assistant (FitBuddy)

## What This Project Is

A web-based fitness tracker with an AI assistant called **FitBuddy**. Users set a profile, log workouts, view progress, and get personalised AI recommendations. Simple, single-user, no database, no auth.

Built as a student submission for the FDE Academy Vibe Coding Lab (Week 1).

## How This Project Is Built

**Spec-driven, session-by-session.** Each session has a spec file created first, then implementation follows against it. Sessions must be executed in order:

1. `.claude/specs/spec-01-scaffold.md` → Project scaffolding
2. `.claude/specs/spec-02-frontend-shell.md` → Frontend UI layout and styling
3. `.claude/specs/spec-03-data-layer.md` → localStorage, forms, progress view, export
4. `.claude/specs/spec-04-ai-integration.md` → `/api/recommend` endpoint, FitBuddy UI, guardrails

Specs are generated by the `/create-spec` command and saved to `.claude/specs/`.

At the start of each session: create the spec file first, get confirmation if needed, then implement.

## Hard Rules

- **No framework.** Vanilla JS only. No React, Vue, or any build toolchain.
- **No database.** `localStorage` only. Keys are `ft_profile` and `ft_log`.
- **API key never in code.** Always read from `process.env.LLM_API_KEY` in `server.js`. Never in frontend files.
- **No extra files.** Do not create files beyond what the spec or structure above defines.
- **No extra features.** Build only what the current session spec describes.
- **`server.js` is the only backend file.** Do not create routes/, controllers/, or any other server-side files.

## Git Setup (required before first session)

This project must be a git repository before using `/create-spec`. The command checks git status, creates feature branches, and checks out `main`.

```bash
git init
git add .
git commit -m "Initial project setup"
```

`/create-spec` will fail at Step 1 if this has not been done.

## Git Workflow per Session

`/create-spec` only creates the feature branch locally. It does **not** push or merge anything.

After each session, once you have reviewed the implementation:

```bash
git add .
git commit -m "Session N: <feature title>"
git push origin <branch_name>   # push the feature branch
git checkout main
git merge <branch_name>
git push origin main
git branch -d <branch_name>     # delete local feature branch
```

Do this manually — the skill will never push or delete branches on your behalf.

## AI Design — FitBuddy

- **Persona:** Friendly, encouraging, evidence-based. Not a doctor.
- **Context sent per request:** user name, age, goal + last 5 activity log entries + current date
- **Endpoint:** `POST /api/recommend` — returns `{ recommendation: "..." }`
- **Guardrail Layer 1:** System prompt rules (no extreme diets, no dangerous advice, always disclaim)
- **Guardrail Layer 2:** Server-side keyword filter on the response before it reaches the frontend
- **Disclaimer shown in UI:** *"FitBuddy is an AI assistant, not a medical professional."*
